2. DNS sur takussan.com (Cloudflare)

TypeNomValeurMode CFPour
CNAMEpreviewcname.vercel-dns.comDNS only (gris)Front Vercel
Apreview.api<IP_VPS>DNS only (gris)API VPS
Pourquoi DNS only sur les deux records ?
  • Vercel : ne JAMAIS proxifier via Cloudflare. Double-CDN, conflits TLS, Vercel ne reçoit pas la vraie IP.
  • API VPS : choix actuel = DNS only. Certbot Let's Encrypt fonctionne nativement, pas de surprise sur les certs. Inconvénient : pas de DDoS protection / WAF devant l'API. Si tu veux passer en Proxied plus tard, il faudra :
    • Repasser TRUSTED_PROXIES sur les CIDR Cloudflare (cf. §10) sinon Request::ip() renverra l'IP CF.
    • Régler Cloudflare SSL en mode "Full (strict)" pour respecter le cert Let's Encrypt.
dig +short preview.takussan.com
dig +short preview.api.takussan.com

5. Script server-setup.sh Takussan

Adapté du modèle CheckPrint. Idempotent — sûr à re-exécuter. Crée l'arbo, le pool PHP-FPM, la queue systemd et le cron Takussan, sans toucher à CheckPrint.

À créer dans le repo Takussan à scripts/server-setup.sh puis transférer sur le VPS et exécuter en root.

scripts/server-setup.sh
#!/usr/bin/env bash
# Setup serveur Takussan préprod (idempotent). À lancer en root.
set -euo pipefail

APP_DIR="/var/www/takussan-preview"
DEPLOY_USER="deploy"
WEB_GROUP="www-data"
POOL_NAME="takussan-preview"
QUEUE_SERVICE="takussan-queue-preview"
PHP_VERSION="8.3"

log() { echo "[setup] $*"; }

[ "$(id -u)" -eq 0 ] || { echo "Run as root"; exit 1; }
id "$DEPLOY_USER" &>/dev/null || { echo "User $DEPLOY_USER manquant (devrait exister via CheckPrint)"; exit 1; }

# 1. Arbo
log "Arbo $APP_DIR"
mkdir -p "$APP_DIR/releases"
mkdir -p "$APP_DIR/shared/storage/app/public"
mkdir -p "$APP_DIR/shared/storage/app/private"
mkdir -p "$APP_DIR/shared/storage/framework/cache/data"
mkdir -p "$APP_DIR/shared/storage/framework/sessions"
mkdir -p "$APP_DIR/shared/storage/framework/views"
mkdir -p "$APP_DIR/shared/storage/framework/testing"
mkdir -p "$APP_DIR/shared/storage/logs"
chown -R "$DEPLOY_USER:$WEB_GROUP" "$APP_DIR"
chmod -R 775 "$APP_DIR/shared/storage"

# 2. Pool PHP-FPM dédié
POOL_FILE="/etc/php/$PHP_VERSION/fpm/pool.d/$POOL_NAME.conf"
log "Pool PHP-FPM $POOL_NAME"
cat > "$POOL_FILE" <<CONF
[$POOL_NAME]
user = $DEPLOY_USER
group = $WEB_GROUP
listen = /run/php/$POOL_NAME.sock
listen.owner = www-data
listen.group = www-data
listen.mode = 0660

pm = dynamic
pm.max_children = 10
pm.start_servers = 2
pm.min_spare_servers = 1
pm.max_spare_servers = 4
pm.max_requests = 500

php_admin_value[error_log] = /var/log/php/$POOL_NAME.error.log
php_admin_flag[log_errors] = on
php_admin_value[memory_limit] = 256M
php_admin_value[upload_max_filesize] = 20M
php_admin_value[post_max_size] = 25M
env[APP_ENV] = preview
CONF
mkdir -p /var/log/php
touch "/var/log/php/$POOL_NAME.error.log"
chown www-data:www-data "/var/log/php/$POOL_NAME.error.log"
systemctl restart "php$PHP_VERSION-fpm"

# 3. Queue worker systemd
SERVICE_FILE="/etc/systemd/system/$QUEUE_SERVICE.service"
log "Queue systemd $QUEUE_SERVICE"
cat > "$SERVICE_FILE" <<UNIT
[Unit]
Description=Takussan Laravel Queue Worker (preview)
After=network.target mysql.service

[Service]
User=$DEPLOY_USER
Group=$WEB_GROUP
WorkingDirectory=$APP_DIR/current
ExecStart=/usr/bin/php artisan queue:work --sleep=3 --tries=3 --max-time=3600
Restart=always
RestartSec=5
StandardOutput=append:$APP_DIR/shared/storage/logs/queue-worker.log
StandardError=append:$APP_DIR/shared/storage/logs/queue-worker.log

[Install]
WantedBy=multi-user.target
UNIT
systemctl daemon-reload
systemctl enable "$QUEUE_SERVICE"
# Ne pas start tant que current/ n'existe pas — sera start au 1er deploy.

# 4. Cron Laravel scheduler
CRON_LINE="* * * * * cd $APP_DIR/current && php artisan schedule:run >> /dev/null 2>&1"
EXISTING=$(crontab -u "$DEPLOY_USER" -l 2>/dev/null || true)
if echo "$EXISTING" | grep -qF "$APP_DIR/current"; then
    log "Cron Takussan préprod déjà présent"
else
    log "Ajout cron Takussan préprod"
    (echo "$EXISTING"; echo "$CRON_LINE") | crontab -u "$DEPLOY_USER" -
fi

log ""
log "=================================================="
log "  Setup Takussan préprod terminé."
log "=================================================="
log "Prochaines étapes :"
log "  - Créer la base MySQL takussan_preview (step 6)"
log "  - Pousser scripts/deploy.sh via GH Actions (step 16)"
log "  - Configurer le vhost nginx (step 8)"
log "  - SSL Let's Encrypt (step 9)"
log "  - Ajouter le secret ENV_FILE_PREVIEW + REPO_URL côté GH"
log "  - Pousser sur la branche preview"

Transfert et exécution :

scp scripts/server-setup.sh admin@<IP_VPS>:/tmp/
ssh admin@<IP_VPS> "sudo bash /tmp/server-setup.sh && rm /tmp/server-setup.sh"

8. Vhost Nginx API

sudo tee /etc/nginx/sites-available/takussan-preview-api > /dev/null <<'CONF'
server {
    listen 80;
    listen [::]:80;
    server_name preview.api.takussan.com;

    root /var/www/takussan-preview/current/public;
    index index.php;

    client_max_body_size 25M;

    access_log /var/log/nginx/takussan-preview-api.access.log;
    error_log  /var/log/nginx/takussan-preview-api.error.log;

    # Storage public (via storage:link)
    location /storage/ {
        alias /var/www/takussan-preview/shared/storage/app/public/;
        expires 7d;
    }

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~ \.php$ {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/run/php/takussan-preview.sock;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        fastcgi_read_timeout 60;
    }

    location ~ /\.(?!well-known) { deny all; }
}
CONF

sudo ln -sf /etc/nginx/sites-available/takussan-preview-api /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
Le deploy.sh Takussan symlie current directement vers releases/<ts> (pas vers un sous-dossier takussan-api/) — voir step 15. Donc root = .../current/public.

10. Préparer le secret ENV_FILE_PREVIEW

Le .env ne vit pas en clair sur le VPS — il est injecté à chaque deploy via secret GH (pattern CheckPrint). Le bloc ci-dessous est l'audit des variables réellement utilisées par le code Takussan, regroupées par domaine. Tout ce qui n'apparaît pas ici tombe sur le default Laravel et reste sain pour préprod.

Audit méthode : grep -rh "env(['\"]" takussan-api/config takussan-api/app | sort -u. Les variables custom Takussan (CDN, SMS, ActivityLog, AccountDeletion, Visits, PDF) sont incluses avec leur default explicite. Les variables Laravel standard non listées (Memcached, Beanstalkd, Pusher, Reverb, Algolia, Postmark, AWS, etc.) ne sont pas activées en préprod et n'ont pas besoin d'être déclarées.

11. CORS + Sanctum cross-domain

takussan-api/config/cors.php

return [
    'paths' => ['api/*', 'sanctum/csrf-cookie', 'login', 'logout', 'storage/*'],
    'allowed_methods' => ['*'],
    'allowed_origins' => [
        env('FRONTEND_URL', 'http://localhost:3000'),
    ],
    'allowed_origins_patterns' => [
        // Builds preview Vercel random : takussan-.vercel.app
        '#^https://takussan-[a-z0-9-]+\.vercel\.app$#',
    ],
    'allowed_headers' => ['*'],
    'exposed_headers' => [],
    'max_age' => 0,
    'supports_credentials' => true,   // OBLIGATOIRE pour Sanctum
];

Côté Next.js

// Toutes les requêtes auth doivent envoyer les cookies
fetch(`${process.env.NEXT_PUBLIC_API_URL}/api/...`, { credentials: 'include' });

// Avant un login Sanctum :
await fetch(`${process.env.NEXT_PUBLIC_API_URL}/sanctum/csrf-cookie`, {
  credentials: 'include',
});
Cookies cross-subdomain : SESSION_DOMAIN=.takussan.com (point en préfixe). Sans le point → cookie posé par l'API non lisible côté front. Couvre preview.takussan.com et preview.api.takussan.com en préprod ; aussi takussan.com / api.takussan.com en prod future, mais SESSION_COOKIE différent par env empêche le partage de session.

Host github.com-takussan

    User git

# → "Hi /takussan! You've successfully authenticated"

15. Script deploy.sh Takussan

Aligné sur le pattern CheckPrint : clone complet du repo dans releases/<ts>/ puis le déploiement opère sur le sous-dossier takussan-api/. Symlinks shared .env et storage/, composer, Vite build, migrate, caches, swap atomique, queue:restart. trap ERR déclenche un rollback automatique (restauration du symlink précédent + suppression du release fautif).

Le fichier est versionné à scripts/deploy.sh dans le repo. Le workflow GH Actions (step 16) le pousse via scp à chaque deploy, donc la version sur le VPS est toujours celle du commit en cours.

Aperçu (extrait — voir scripts/deploy.sh pour la version complète) :

#!/usr/bin/env bash
# deploy.sh — Zero-downtime deployment for Takussan (Laravel API)
# Usage: deploy.sh  [branch] [app-dir]
set -euo pipefail

BRANCH="${2:-master}"
APP_DIR="${3:-/var/www/takussan}"
RELEASES_DIR="$APP_DIR/releases"
SHARED_DIR="$APP_DIR/shared"
CURRENT_LINK="$APP_DIR/current"
KEEP_RELEASES=5
TIMESTAMP=$(date +%Y%m%d%H%M%S)
RELEASE_DIR="$RELEASES_DIR/$TIMESTAMP"

REPO_URL="${1:?Usage: deploy.sh  [branch] [app-dir]}"

PREVIOUS_RELEASE=""

log() { echo "[deploy] $(date '+%H:%M:%S') $*"; }

get_previous_release() {
    if [ -L "$CURRENT_LINK" ]; then
        readlink -f "$CURRENT_LINK"
    fi
}

rollback() {
    local exit_code=$?
    log "ERROR (exit=$exit_code). Rolling back..."
    if [ -n "$PREVIOUS_RELEASE" ] && [ -d "$PREVIOUS_RELEASE" ]; then
        log "Restoring symlink to $PREVIOUS_RELEASE"
        ln -sfn "$PREVIOUS_RELEASE" "$CURRENT_LINK.tmp" && mv -Tf "$CURRENT_LINK.tmp" "$CURRENT_LINK"
    fi
    if [ -d "$RELEASE_DIR" ]; then
        log "Removing failed release $RELEASE_DIR"
        rm -rf "$RELEASE_DIR"
    fi
    log "Rollback done."
    exit 1
}
trap rollback ERR

log "Starting deploy"
log "Repo=$REPO_URL  Branch=$BRANCH  AppDir=$APP_DIR  Release=$TIMESTAMP"

[ -d "$SHARED_DIR" ] || { log "FATAL: $SHARED_DIR missing — run server-setup.sh first"; exit 1; }

# Écrire .env depuis le secret GH si fourni
if [ -n "${ENV_FILE:-}" ]; then
    log "Writing .env from ENV_FILE secret"
    echo "$ENV_FILE" > "$SHARED_DIR/.env"
    chown deploy:www-data "$SHARED_DIR/.env"
    chmod 640 "$SHARED_DIR/.env"
elif [ ! -f "$SHARED_DIR/.env" ]; then
    log "FATAL: pas de ENV_FILE et $SHARED_DIR/.env absent"
    exit 1
fi

[ -d "$SHARED_DIR/storage" ] || { log "FATAL: $SHARED_DIR/storage missing"; exit 1; }

PREVIOUS_RELEASE=$(get_previous_release)
[ -n "$PREVIOUS_RELEASE" ] && log "Previous release: $PREVIOUS_RELEASE" || log "First deploy."

mkdir -p "$RELEASES_DIR"

# 1. Clone complet du monorepo dans releases//
git clone --depth 1 --branch "$BRANCH" "$REPO_URL" "$RELEASE_DIR"

# 2. Symlinks shared sur le sous-dossier takussan-api/
rm -f  "$RELEASE_DIR/takussan-api/.env"
ln -sfn "$SHARED_DIR/.env" "$RELEASE_DIR/takussan-api/.env"
rm -rf "$RELEASE_DIR/takussan-api/storage"
ln -sfn "$SHARED_DIR/storage" "$RELEASE_DIR/takussan-api/storage"

# 3. Composer + npm + migrate + caches + storage:link
cd "$RELEASE_DIR/takussan-api"
composer install --no-dev --no-interaction --prefer-dist --optimize-autoloader
npm ci --no-audit --no-fund && npm run build
php artisan migrate --force
php artisan config:cache && php artisan route:cache && php artisan view:cache
php artisan storage:link

# 4. Swap atomique : current → releases//takussan-api
ln -sfn "$RELEASE_DIR/takussan-api" "$CURRENT_LINK.tmp"
mv -Tf  "$CURRENT_LINK.tmp" "$CURRENT_LINK"

# 5. Restart queue (signal au worker systemd qui fait Restart=always)
cd "$CURRENT_LINK"
php artisan queue:restart 2>/dev/null || true

# 6. Cleanup : garde les KEEP_RELEASES dernières
Pourquoi pas de sudo systemctl restart php8.3-fpm ? Le pattern CheckPrint s'appuie sur opcache.validate_timestamps (défaut PHP = 2s) — quand composer install et les artisan *:cache écrivent de nouveaux fichiers, opcache les pickup automatiquement. Le worker queue, lui, est signalé par php artisan queue:restart et redémarré par systemd grâce à Restart=always dès qu'il finit son job en cours. Aucun privilège sudo n'est requis côté deploy pour cette boucle. Avantage : moins de friction sudoers. Inconvénient : la fenêtre opcache peut servir du code stale ~2s post-swap.

18. Rollback

Automatique (script)

Le trap rollback ERR dans deploy.sh restaure le symlink current sur la release précédente si une étape post-clone échoue. Aucune action manuelle requise.

Manuel (rollback après coup)

ssh deploy@<IP_VPS>
cd /var/www/takussan-preview/releases
ls -1t
# Pointer current vers la release précédente. Note : current pointe sur
# releases//takussan-api (sous-dossier), pas releases/.
ln -sfn /var/www/takussan-preview/releases/<ID_PRECEDENT>/takussan-api \
       /var/www/takussan-preview/current
# Signaler la queue worker pour qu'elle reload le code (Restart=always la
# relance après son prochain job). Opcache picke le code en ~2s.
cd /var/www/takussan-preview/current && php artisan queue:restart

Front (Vercel)

Dashboard Vercel → Deployments → trouver le deploy précédent stable → menu ··· → Promote ou Rollback.

⚠️ Le rollback automatique restaure le code mais pas la DB. Si la release fautive a tourné migrate --force, le schéma reste en avant. Toujours écrire des migrations rétrocompatibles (ajouter colonnes nullable, jamais drop sans 2 deploys).

20. Dépannage

CORS error côté Next.js
  • "No 'Access-Control-Allow-Origin' header" → FRONTEND_URL dans le secret ENV_FILE_PREVIEW ne match pas l'origin. Redéployer après correction.
  • "...Access-Control-Allow-Credentials is not 'true'" → supports_credentials => true dans config/cors.php. Re-cache : php artisan config:cache (sur prochain deploy auto).
Login passe mais requêtes suivantes 401
  • credentials: 'include' oublié côté Next.
  • SESSION_DOMAIN sans point devant.
  • SESSION_SAME_SITE=strict → mettre lax.
  • HTTPS manquant sur un des deux côtés.
deploy.sh : "Permission denied (publickey)" lors du git clone

La Deploy Key (step 12) n'est pas en place ou l'alias SSH n'est pas utilisé.

ssh -T github.com-takussan
# doit dire "Hi /takussan!"
# Si non : revoir ~/.ssh/config et la deploy key dans GH
Queue worker ne consomme pas les jobs après deploy

php artisan queue:restart envoie juste un signal — le worker en cours finit son job puis exit. Restart=always dans systemd le redémarre automatiquement. Vérifier :

sudo systemctl status takussan-queue-preview --no-pager
sudo journalctl -u takussan-queue-preview -n 50 --no-pager
# Si DOWN : sudo systemctl start takussan-queue-preview
502 Bad Gateway sur l'API 
# Le pool PHP-FPM (par défaut) tourne-t-il ?
sudo systemctl status php8.3-fpm
sudo tail -30 /var/log/nginx/takussan-preview-api.error.log
# Vhost pointe-t-il sur le bon socket ? Si tu utilises un pool dédié :
sudo php-fpm8.3 -tt 2>&1 | grep -i takussan
Certbot timeout sur l'API

Vérifier que le record A preview.api.takussan.com dans Cloudflare est bien en DNS only (gris) et propagé (dig +short preview.api.takussan.com). Si tu décides plus tard de passer en Proxied (orange) avec SSL "Full (strict)", le challenge HTTP-01 fonctionne quand même tant que Cloudflare n'intercepte pas /.well-known/acme-challenge/. Alternative robuste : certbot --dns-cloudflare avec un API token CF (challenge DNS-01, fonctionne quel que soit le mode).

Le secret ENV_FILE_PREVIEW n'arrive pas dans deploy.sh

Vérifier dans le workflow que envs: ENV_FILE et env: ENV_FILE: ${{ secrets.ENV_FILE_PREVIEW }} sont bien tous les deux présents dans le step appleboy/ssh-action.

Cron scheduler ne se déclenche pas 
sudo crontab -u deploy -l | grep takussan-preview
# Si absent : re-rouler server-setup.sh
sudo grep CRON /var/log/syslog | tail -20
deploy.sh : cd: takussan-api: No such file or directory

Le clone complet du repo doit contenir takussan-api/ à la racine. Si le sous-dossier est renommé ou bougé, deploy.sh casse. Vérifier sur le serveur :

# → doit contenir takussan-api/ takussan-web/ docs/ ...

Si le repo a changé de structure, mettre à jour les occurrences takussan-api dans scripts/deploy.sh.
