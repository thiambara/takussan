# Radar, TCK-2388 : fiche annonceur, message d'accord à clauses fixes, preuve d'accord vérifiée puis confirmée, plan d'implémentation

> **Pour les agents :** compétence requise : `superpowers:subagent-driven-development`, tâche par
> tâche. Les étapes se cochent (`- [ ]`). Plan **temporaire** (règle du dépôt). Le contrat est le
> ticket [TCK-2388](../backlog/tickets/TCK-2388-radar-demarchage-et-preuve-d-accord.md). La vérité est
> dans [ADR-0077](../adr/0077-le-radar.md) (§2 à §5, §8, §9, §11), [ADR-0076 §7, §8, §10](../adr/0076-le-socle-ia.md)
> (suggestions, évaluations, contenu externe), [ADR-0043 §7](../adr/0043-moderation-unifiee.md) (prise en
> charge), le [plan du Radar](2026-10-26-radar-et-socle-ia.md) (« Les données », écran 4, « Les usages IA »,
> « Le message d'accord — clauses fixes (v1) ») et [features §2.12](../features.md#212-radar--acquisition-dannonces).
> Il s'appuie sur TCK-2386 et TCK-2387, sur la même branche `feat/radar-relecture`.

**Objectif :** un opérateur (`support` et au-dessus) ouvre la fiche d'un annonceur. Il la prend en charge
pour dix minutes, renouvelables ; un second opérateur qui écrit pendant ce temps reçoit 409. Il coche une ou
plusieurs annonces `reviewed`, choisit la langue, et l'API prépare **un** message : des clauses fixes lues dans
le dépôt, une salutation et un résumé écrits par l'IA et retouchables, et le lien `wa.me` vers le seul numéro
de l'annonceur, dont le paramètre `text` est **exactement** le texte enregistré. Il ouvre WhatsApp, envoie,
confirme l'envoi. Il dépose les captures de la réponse ; l'IA les transcrit, vérifie le numéro et les
clauses, classe la réponse. Il confirme ou corrige : un accord confirmé couvre toutes les annonces du message ;
un STOP rend l'annonceur `do_not_contact`, définitivement. Les relances dues remontent d'elles-mêmes.

**Architecture :**

- **Données.** `radar_outreaches` (un message : texte exact, version des clauses, langue, auteur, envoi,
  issue, chaîne de relances), `radar_outreach_listing` (les annonces qu'il couvre), `radar_consents` (une
  réponse déposée : type de preuve, captures et leurs SHA-256, transcription, verdict IA, confirmation
  humaine, révocation). La prise en charge vit **sur la ligne de l'annonceur** (`claimed_by_id`,
  `claim_expires_at`) : sa ligne est le point de sérialisation (piège PostgreSQL n° 2), sans table de plus.
- **Message.** `ConsentMessageComposer` lit `resources/radar/clauses/accord.v1.<locale>.md`, découpe le
  gabarit en segments (`fixed`, `salutation`, `resume`), y place les deux parties produites par l'usage
  `radar.message_accord` (rôle `redaction`), et rend le texte et le lien `wa.me`. Le texte est la
  concaténation des segments : rien d'autre ne l'écrit.
- **Réponse.** `POST …/reply` range les captures (mêmes règles que la saisie de TCK-2386, extraites dans
  `RadarCaptureReader`), crée la `radar_consents` en `verification_status = pending` et met en file
  `VerifyRadarConsentReply`, qui appelle `radar.verification_accord` (rôle `raisonnement`, `vision` avec des
  captures) **hors de la requête**, puis écrit le verdict, relu par du code (`RadarConsentVerdict`).
- **Issue.** `POST …/outcome` est le seul geste qui confirme : `consented` (contre une réponse déposée ; motif
  écrit exigé si le verdict est discordant ou absent), `refused`, `stop`, `question`, `no_answer`. Il
  verrouille **les annonces, puis l'annonceur, puis le message, puis la réponse** : l'ordre de TCK-2386 et de
  `PUT …/listings/{listing}/advertiser`.
- **Couverture.** `RadarConsentCoverage` est LA définition d'une annonce couverte par un accord valide
  (confirmé, non révoqué) : la préparation la lit ici (422), TCK-2389 la lira pour publier.
- **Front.** `/super-admin/radar/advertisers` (files « à contacter », « en attente », « à relancer ») et
  `/super-admin/radar/advertisers/[id]` (la fiche, poste de travail du démarchage).

**Stack :** Laravel 13 / PHP 8.4, `laravel/ai` ^1.3, GD, PostgreSQL 17. Front : Next.js 16 / React 19 /
TanStack Query / next-intl, Vitest.

## Décisions du porteur (confirmées le 2026-10-28)

Chaque endroit qui en dépend est marqué « (décision N, porteur 2026-10-28) ».

1. **Lien de réclamation.** La page arrive avec TCK-2390. `accord.v1.*.md` est le texte du plan **sans** la
   ligne « Vous préférez vérifier vous-même avant ? {lien_reclamation} » ; TCK-2390 l'ajoutera en `accord.v2`.
   Chaque message garde la version des clauses qu'il a employée (`clauses_version`).
2. **`{lien_conditions}`** : `App\Support\LienFront::vers('/{locale}/legal/terms')` (la base du front,
   `config('app.frontend_url')`, déjà LA forme des liens vers le front ; la page existe :
   `takussan-web/src/app/[locale]/(public)/legal/terms/page.tsx`). Aucun message réel ne part avant la production.
3. **Nature de l'annonceur.** À la validation d'une annonce (`RadarListingReview::review()`), si l'opérateur a
   corrigé `extracted.advertiser_nature` (marque `corrected`), la valeur devient `radar_advertisers.nature` : la
   dernière relecture humaine l'emporte. Les indices de l'IA (`nature_signals`) restent.
4. **Relances.** Un message `sent` sans issue depuis 3 jours entre dans la file « à relancer » ; une relance est
   un nouveau message sur les mêmes annonces ; après 2 relances sans réponse, la file propose `no_answer`. Les
   deux chiffres vivent dans `config('radar.follow_ups')`, et nulle part ailleurs.
5. **Langue du message** : `fr` ou `en`, `fr` par défaut, pas de `wo` (wolof en pause).
6. **Jeu d'évaluation de `radar.verification_accord`** : captures **synthétiques** (conversations façon
   WhatsApp rendues par un script versionné, numéros fictifs), anonymes par construction, avec un README qui le
   dit. La **référence** (`baseline.json`) contre le vrai modèle n'est pas dans ce ticket : elle part avec le
   passage payant de TCK-2403. AC6 se livre donc ainsi : le jeu existe, et `ai:eval radar.verification_accord`
   le joue jusqu'au bout, en succès, sur faux modèle dans les tests.

## Contraintes globales

- **Aucun test ne joint un vrai modèle ni le réseau.** `RadarConsentMessage::fake()`,
  `RadarConsentVerification::fake()` (SDK), `Http::preventStrayRequests()` ; la socle d'essai
  (`Tests\Support\Ai\SocleIaDEssai`) avec le catalogue et les prompts **réels**
  (`new AiUsageRegistry`, `new PromptRepository`), comme `ExtractRadarListingTest`. Les tests qui déposent une
  réponse sous `sync` jouent le job de vérification : faux modèle obligatoire, ou `Bus::fake([VerifyRadarConsentReply::class])`
  quand le test ne porte pas sur le verdict.
- **Les clauses sont du texte du dépôt, jamais une génération.** L'IA ne produit que `{salutation}` et
  `{resume}`. Une clé de plus dans sa sortie est ignorée ; ses deux parties sont ramenées à une ligne (aucun saut
  de ligne ne peut y imiter une clause numérotée) et bornées en longueur.
- **Le lien `wa.me` ne porte que le numéro de l'annonceur** (`radar_advertisers.phone`). Aucune lecture de
  `config('whatsapp')` ni de l'intégration `whatsapp_cloud` dans ce ticket : le numéro des notifications ne sert
  jamais à prospecter (ADR-0077 §5).
- **Un verdict IA n'ouvre rien.** Seul `POST …/outcome` écrit `confirmed_by_id` et `confirmed_at`. Un accord
  valide = `confirmed_at` non nul et `revoked_at` nul (`RadarConsent::scopeValid()`), lu par
  `RadarConsentCoverage`, nulle part ailleurs.
- **STOP** : `do_not_contact_at` posé, l'empreinte `phone_hmac` relue contre `RadarPhone::hmac($phone)` (elle
  existe depuis la création, colonne NOT NULL de TCK-2386 : on la vérifie, on n'en écrit pas une seconde) ;
  `RadarAdvertiserDirectory::refusedAmong()` la retrouve ensuite. Pas de purge ici (TCK-2391).
- **Ordre des verrous**, partout où plusieurs lignes se verrouillent : **annonces (par id croissant) →
  annonceur → message → réponse.** C'est celui de `ExtractRadarListing` et de
  `RadarListingReview::setAdvertiser()` (annonce → annonceur). Un geste qui n'a pas besoin des annonces commence
  à l'annonceur. Aucun appel au modèle n'a lieu sous un verrou ni dans une transaction.
- **Prise en charge** : 10 minutes (`AdvertiserClaim::DURATION_MINUTES`), renouvelée par `POST …/claim` et par
  chaque écriture. **Toute écriture de ce ticket exige de la tenir** : sans elle, 409
  `radar.advertiser.claim_required` ; tenue par un autre, 409 `radar.advertiser.claimed_by_other`
  (`params.claimed_until`). La lecture n'en exige pas.
- **Captures** : mêmes règles que la saisie (`config('radar.captures')` : type relu dans le contenu, taille,
  nombre, budget de pixels lu dans l'en-tête avant tout décodage, réencodage qui retire l'EXIF), SHA-256 de
  l'original gardé dans `radar_consents.capture_hashes` **et** en propriété du média. Disque **privé** par défaut
  (ADR-0029), servies par URL signée (`PrivateMediaAccess::signedUrl()`), aucune route neuve.
- **Droits** : toutes les routes sous `auth:sanctum` + `super-admin` + `platform-can:platform.radar.operate`
  (`routes/api/admin-radar.php`). FormRequests sur `BaseFormRequest`, `authorize(): true` (gardées par la route,
  comme TCK-2386/2387).
- **Codes, jamais de prose** dans les réponses (`abort_code*`). **Chaque code neuf** existe dans
  `lang/{fr,en,wo}/errors.php` (wo = le texte français) **et** dans la table du front (`codes-radar.ts`). TCK-2387
  a cassé `LangGroupParityTest` et `DateInventoryByValueTest` en l'oubliant : **chaque tâche backend lance
  `php artisan test tests/Unit` en plus de ses fichiers**. Une clé de ressource neuve que le parcours de
  `DateInventoryByValueTest` n'atteint pas s'ajoute à `CLES_JAMAIS_ATTEINTES` avec sa raison, comme
  `RadarListingResource::neighborhood_link` ; toute date émise passe par `iso()`.
- **Routes** : chaque route neuve entre dans `PlatformRoutesDefaultDenyTest::SUPPORT_EN_PLUS` ; un paramètre neuf
  (`{advertiser}`, `{outreach}`) reçoit une **ligne réelle** dans `NamespaceAccessGuardTest` (factory créée,
  `strtr`), sinon le `1` de remplacement rend 404 au lieu de 403.
- **Écritures journalisées** : `activity('Admin')->causedBy()->performedOn()->withProperties()->event()->log()`,
  comme `RadarListingReview::journal()`. Le journal ne porte **jamais** un numéro ni le texte d'un message ; le
  motif écrit d'une confirmation discordante, si (le ticket l'exige).
- **Migrations PostgreSQL** (`takussan-api/CLAUDE.md`, « Migrations ») : `jsonb` seulement, `string()` (jamais
  `enum()`), noms d'index, de FK et de contraintes explicites sous 63 caractères, FK indexées, `down()` exact ;
  aucune exception attrapée dans une transaction (`insertOrIgnore` puis relecture) ;
  `Rule::exists()->where('col', false)` lève sous pgsql : forme en fermeture.
- **API** : `Base\Controller` + `$this->json()` ; enums sous `app/Models/Enums/` ; ressources sur `BaseResource`
  (`whenHas`, `iso()`, `enumValue()`) sous `app/Http/Resources/Api/Admin/` ; requêtes sous
  `app/Http/Requests/Api/Admin/` ; services sous `app/Services/Radar/`.
- **Socle IA** : un usage = un fichier de `app/Ai/Usages/` listé dans `AiUsageRegistry::USAGES`, un agent sous
  `app/Ai/Agents/` (sortie structurée, ni outil ni compétence : ADR-0076 §10), un prompt
  `resources/ai/prompts/<usage>/v1.md` inscrit dans `versions.lock.json` (`shasum -a 256`,
  `PromptVersionsAreFrozenTest`). `node scripts/check-ai-usages.mjs` et `node scripts/check-ai-evals-pii.mjs`
  verts. Aucun identifiant de modèle hors de `config/ai.php`.
- **Files (ADR-0078)** : `$timeout` + 5 ≤ `retry_after` de la connexion (90 s pour `database`) ;
  `node scripts/check-queues.mjs` vert. La vérification part sur la file `default`, comme l'extraction ;
  TCK-2402 déplacera les deux.
- **Front** : textes next-intl (`fr`, `en` ; `wo` = le texte français tel quel) ; jetons du design system

  dictionnaire (`src/test/__tests__/promesses-de-delai.test.ts`) : les échéances s'affichent depuis les dates que
  rend l'API.
- `./vendor/bin/pint` avant chaque commit. Commits en français, préfixe conventionnel, `(TCK-2388)` et la ligne

- **Jamais la suite entière en local** (règle du porteur). Un agent ne lance que ses fichiers :

```php
/**
 * TCK-2388 (ADR-0077 §11, modèle d'ADR-0043 §7) — un seul opérateur à la fois sur un annonceur, pour
 * {@see self::DURATION_MINUTES} minutes, renouvelables. La prise vit sur la ligne de l'annonceur : la verrouiller
 * suffit à départager deux prises simultanées (aucune insertion disputée, donc pas d'`insertOrIgnore` ici,
 * contrairement à `moderation_claims`). Une prise expirée d'un autre se reprend.
 *
 * {@see self::assertHeld()} s'appelle DANS la transaction d'un geste, sur l'annonceur que ce geste vient de
 * verrouiller APRÈS ses annonces (ordre : annonces → annonceur → message → réponse).
 */
final class AdvertiserClaim
{
    public const DURATION_MINUTES = 10;

    public function claim(RadarAdvertiser $advertiser, User $by): RadarAdvertiser
    {
        return DB::transaction(function () use ($advertiser, $by): RadarAdvertiser {
            $locked = RadarAdvertiser::query()->whereKey($advertiser->getKey())->lockForUpdate()->firstOrFail();
            $this->refuseIfHeldByOther($locked, $by);
            $this->stamp($locked, $by);

            return $locked->load('claimer:id,first_name,last_name');
        });
    }

    /** Rendre sa prise. Celle d'un autre, encore active : 409. Aucune prise : rien. */
    public function release(RadarAdvertiser $advertiser, User $by): void
    {
        DB::transaction(function () use ($advertiser, $by): void {
            $locked = RadarAdvertiser::query()->whereKey($advertiser->getKey())->lockForUpdate()->firstOrFail();
            abort_code_if($this->heldByOther($locked, $by), 409, 'radar.advertiser.claim_not_held');
            $locked->forceFill(['claimed_by_id' => null, 'claimed_at' => null, 'claim_expires_at' => null])->save();
        });
    }

    /** Sur un annonceur DÉJÀ verrouillé par l'appelant : tenue par lui, sinon 409 ; renouvelée. */
    public function assertHeld(RadarAdvertiser $locked, User $by): void
    {
        $this->refuseIfHeldByOther($locked, $by);
        abort_code_unless(
            $locked->claimed_by_id === $by->id && $locked->claim_expires_at?->isFuture() === true,
            409,
            'radar.advertiser.claim_required',
        );
        $this->stamp($locked, $by);
    }

    private function refuseIfHeldByOther(RadarAdvertiser $locked, User $by): void
    {
        abort_code_if($this->heldByOther($locked, $by), 409, 'radar.advertiser.claimed_by_other', [
            'claimed_until' => $locked->claim_expires_at?->toIso8601String(),
        ]);
    }

    private function heldByOther(RadarAdvertiser $a, User $by): bool
    {
        return $a->claimed_by_id !== null && $a->claimed_by_id !== $by->id && $a->claim_expires_at?->isFuture() === true;
    }

    private function stamp(RadarAdvertiser $a, User $by): void
    {
        $now = now();
        $a->forceFill([
            'claimed_by_id' => $by->id,
            'claimed_at' => $now,
            'claim_expires_at' => $now->copy()->addMinutes(self::DURATION_MINUTES),
        ])->save();
    }
}
```

        if (! is_file($path)) {
            throw new RuntimeException('radar.clauses_missing');
        }

        return rtrim((string) file_get_contents($path), "\n");
    }

    /** @return list<array{kind: 'fixed'|'salutation'|'resume', text: string}> */
    public function segments(string $locale, string $salutation, string $summary, string $version = self::CLAUSES_VERSION): array
    {
        $parts = preg_split(self::PLACEHOLDER, $this->template($locale, $version), -1, PREG_SPLIT_DELIM_CAPTURE) ?: [];
        $segments = [];
        foreach ($parts as $i => $part) {
            if ($i % 2 === 0) {
                if ($part !== '') {
                    $segments[] = ['kind' => 'fixed', 'text' => $part];
                }

                continue;
            }
            $segments[] = match ($part) {
                'salutation' => ['kind' => 'salutation', 'text' => self::part($salutation, self::SALUTATION_MAX)],
                'resume' => ['kind' => 'resume', 'text' => self::part($summary, self::SUMMARY_MAX)],
                'lien_conditions' => ['kind' => 'fixed', 'text' => $this->conditionsUrl($locale)],
            };
        }

        return $segments;
    }

    public function compose(string $locale, string $salutation, string $summary, string $version = self::CLAUSES_VERSION): string
    {
        return implode('', array_column($this->segments($locale, $salutation, $summary, $version), 'text'));
    }

    /** (décision 2, porteur 2026-10-28) — la page des conditions du front, dans la langue du message. */
    public function conditionsUrl(string $locale): string
    {
        return LienFront::vers("/{$locale}/legal/terms");
    }

    /** Le lien `wa.me` : le numéro de l'ANNONCEUR seul (ADR-0077 §5), et le texte exact. */
    public function waMeUrl(string $e164, string $message): string
    {
        return 'https://wa.me/'.ltrim($e164, '+').'?text='.rawurlencode($message);
    }

    /** Le nombre de clauses numérotées d'une version : la vérification les cherche toutes sur la capture. */
    public function clauseCount(string $version = self::CLAUSES_VERSION): int
    {
        return preg_match_all('/^\d+\. /m', $this->template(self::DEFAULT_LOCALE, $version));
    }

    public static function part(string $raw, int $max): string
    {
        $line = (string) preg_replace('/[\p{Cc}\p{Zl}\p{Zp}\s]+/u', ' ', $raw);

        return mb_substr(trim($line), 0, $max);
    }

    /**
     * La salutation et le résumé, par l'usage `radar.message_accord`. Un refus ou une panne de la passerelle ne
     * bloque pas la préparation : les deux parties restent vides, `error` porte le code, et l'opérateur les
     * écrit lui-même (le lien `wa.me` n'existe qu'une fois les deux remplies).
     *
     * @param  Collection<int, RadarListing>  $listings
     * @return array{salutation: string, summary: string, result: ?AiResult, error: ?string}
     */
    public function generate(RadarAdvertiser $advertiser, Collection $listings, string $locale, int $followUpRank, User $by): array
    {
        try {
            $result = $this->gateway->run(new AiRequest(
                RadarConsentMessageUsage::KEY,
                RadarConsentMessage::input($advertiser->display_name, $locale, $listings->map(self::facts(...))->values()->all(), $followUpRank),
                [AiDataClass::Personnelle],
                actor: $by,
                subject: $advertiser,
            ));
        } catch (AiRefused $e) {
            return ['salutation' => '', 'summary' => '', 'result' => null, 'error' => 'ai.'.$e->reason->value];
        } catch (AiUnavailable $e) {
            return ['salutation' => '', 'summary' => '', 'result' => null, 'error' => $e->getMessage()];
        } catch (Throwable $e) {
            report($e);

            return ['salutation' => '', 'summary' => '', 'result' => null, 'error' => AiErrorCode::fromThrowable($e)];
        }
        // Seules ces deux clés sont lues : toute autre (une « clause » inventée) est ignorée.
        $salutation = self::part(is_string($result->structured['salutation'] ?? null) ? $result->structured['salutation'] : '', self::SALUTATION_MAX);
        $summary = self::part(is_string($result->structured['resume'] ?? null) ? $result->structured['resume'] : '', self::SUMMARY_MAX);

        return [
            'salutation' => $salutation,
            'summary' => $summary,
            'result' => $result,
            'error' => $salutation === '' || $summary === '' ? 'radar.message.generation_incomplete' : null,
        ];
    }

    /** Ce que le modèle reçoit d'une annonce : ses valeurs relues, ni téléphone ni nom. @return array<string, mixed> */
    private static function facts(RadarListing $listing): array
    {
        $v = RadarReviewFields::values($listing->extracted ?? []);

        return array_intersect_key($v, array_flip(['property_type', 'contract', 'rent_period', 'price', 'neighborhood', 'bedrooms', 'title']));
    }
}

/**
 * TCK-2388 (ADR-0077 §2, §3) — LA définition d'une annonce couverte : elle figure dans un message dont une
 * réponse a un accord VALIDE (confirmé par un humain, non révoqué). La préparation d'un message la lit ici

final class RadarConsentCoverage
{
    /** @param  list<int>  $listingIds  @return list<int> celles qui sont couvertes */
    public function coveredAmong(array $listingIds): array
    {
        if ($listingIds === []) {
            return [];

        return DB::table('radar_outreach_listing as ol')
            ->join('radar_consents as c', 'c.radar_outreach_id', '=', 'ol.radar_outreach_id')

            ->whereNotNull('c.confirmed_at')->whereNull('c.revoked_at')
            ->distinct()->orderBy('ol.radar_listing_id')
            ->pluck('ol.radar_listing_id')->map(fn ($id) => (int) $id)->all();
    }

    /** @return list<int> */
    public function coveredListingIds(RadarAdvertiser $advertiser): array { /* même jointure, par c.radar_advertiser_id */ }

**Logique :**

```php
/**
 * TCK-2388 (ADR-0077 §3, §8) — le SEUL geste qui confirme une réponse. Un verdict IA n'ouvre rien : seul ce
 * geste écrit `confirmed_by_id` et `confirmed_at`. `consented` exige une réponse déposée, et un motif écrit
 * (journalisé) quand le verdict est discordant ou absent ({@see RadarConsentVerdict::discordances()}).
 * `refused`, `stop`, `question` et `no_answer` s'enregistrent avec ou sans capture.
 *
 * Ordre des verrous : les annonces (par id), puis l'annonceur, puis le message, puis la réponse — celui
 * d'`ExtractRadarListing` et de `PUT …/listings/{listing}/advertiser`. Un STOP verrouille TOUTES les annonces de
 * l'annonceur, puisqu'il les ferme toutes.
 */
public function recordOutcome(RadarOutreach $outreach, RadarOutreachOutcome $outcome, ?string $reason, User $by): RadarOutreach
{
    return DB::transaction(function () use ($outreach, $outcome, $reason, $by): RadarOutreach {
        $ids = $outcome === RadarOutreachOutcome::Stop
            ? RadarListing::query()->where('radar_advertiser_id', $outreach->radar_advertiser_id)->pluck('id')->all()
            : $outreach->listings()->pluck('radar_listings.id')->all();
        $listings = RadarListing::query()->whereIn('id', $ids)->orderBy('id')->lockForUpdate()->get();
        $advertiser = RadarAdvertiser::query()->whereKey($outreach->radar_advertiser_id)->lockForUpdate()->firstOrFail();
        $this->claims->assertHeld($advertiser, $by);
        abort_code_if($advertiser->do_not_contact_at !== null, 422, 'radar.advertiser.do_not_contact');

        $o = RadarOutreach::query()->whereKey($outreach->getKey())->lockForUpdate()->firstOrFail();
        abort_code_if($o->sent_at === null, 409, 'radar.outreach.not_sent');
        abort_code_if($o->outcome?->isFinal() === true, 409, 'radar.outreach.outcome_final', ['outcome' => $o->outcome?->value]);
        abort_code_if($o->followUp()->exists(), 409, 'radar.outreach.superseded');
        $reply = $o->consents()->latest('id')->lockForUpdate()->first();

        match ($outcome) {
            RadarOutreachOutcome::Consented => $this->consent($o, $reply, $listings, $reason, $by),
            RadarOutreachOutcome::Refused => $this->move($listings, $o, RadarListingStage::Refused),
            RadarOutreachOutcome::Stop => $this->stop($advertiser, $listings),
            RadarOutreachOutcome::Question, RadarOutreachOutcome::NoAnswer => null,
        };
        $o->forceFill(['outcome' => $outcome, 'outcome_at' => now(), 'outcome_by_id' => $by->id])->save();
        $this->decideVerification($reply, $outcome, $by);
        $this->journal(/* radar_outreach_outcome : outreach_id, outcome, consent_id, listing_ids, discordances, reason */);

        return $o->refresh();
    });
}
```

- **`consent()`** :
  - aucune réponse déposée → 422 `radar.consent.reply_required` ;
  - `$d = RadarConsentVerdict::discordances($reply)` ; `$d !== []` et motif vide → 422 `radar.consent.reason_required`
    (`params.discordances`) ;
  - la réponse : `confirmed_by_id`, `confirmed_at`, `confirmation_reason` (le motif si discordant, sinon null) ;
  - **toutes** les annonces du message encore `contacted` passent `consented` (AC2) ; une annonce du message qui n'est
    plus `contacted` (cas qui ne devrait pas se produire : un message envoyé ne se ferme pas par la relecture) → 409
    `radar.listing.stage_conflict`.
- **`move()`** (`refused`) : les annonces du message encore `contacted` passent `refused`.
- **`stop()`** :
  - `do_not_contact_at = now()` ;
  - l'empreinte : si `phone` n'est pas nul et que `phone_hmac !== RadarPhone::hmac($phone)` (clé changée depuis la
    création), elle est réécrite ; sinon elle reste, posée depuis TCK-2386 ;
  - chaque annonce de l'annonceur à l'étape `extracted`, `reviewed`, `contacted` ou `consented` passe `do_not_contact`
    (les annonces closes — `duplicate`, `discarded`, `refused`, `purged` — restent ; `published` n'existe pas avant

  - `phone` et `raw_text` **ne sont pas purgés** ici (TCK-2391, « dès un STOP »).
- **`decideVerification()`** : la suggestion `radar.verification_accord` en attente de la réponse, si elle existe, se
