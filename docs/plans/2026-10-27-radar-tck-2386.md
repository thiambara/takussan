# Radar, TCK-2386 — saisie d'une annonce et extraction IA — plan d'implémentation

> **Pour les agents :** compétence requise : `superpowers:subagent-driven-development`, tâche par
> tâche. Les étapes se cochent (`- [ ]`). Plan **temporaire** (règle du dépôt) : le contrat est le
> ticket [TCK-2386](../backlog/tickets/TCK-2386-radar-saisie-et-extraction.md), la vérité
> [ADR-0077](../adr/0077-le-radar.md) et [features §2.12](../features.md#212-radar--acquisition-dannonces).

**Objectif :** un opérateur (`support` et au-dessus) colle une ou plusieurs URL, un texte ou des
captures ; l'annonce est enregistrée hors du catalogue (`radar_listings`), puis un job en extrait
les champs du bien par l'usage IA `radar.extraction`, chacun avec sa valeur, sa confiance et le
passage cité, normalisés par du code (montants, bornes, quartier).

**Architecture :** `POST /api/admin/radar/listings` → `RadarListingIntake` (empreinte unique, refus
STOP, captures sans EXIF) → job `ExtractRadarListing` → (`UrlFetcher` + `HtmlCleaner` pour une URL)
→ `AiGateway::run()` usage `radar.extraction` → `ExtractionNormalizer` → annonceur retrouvé ou créé
par son téléphone. Le front sert un tableau de bord et un panneau de saisie sous `/super-admin/radar`.

**Stack :** Laravel 13 / PHP 8.4, `laravel/ai` ^1.3, `intervention/image` ^4.2, PostgreSQL 17,
Next.js 16 / React 19 / TanStack Query / next-intl, Vitest.

## Contraintes globales

- **Aucun test ne joint un vrai modèle ni le réseau** : `RadarExtraction::fake()` (SDK), `Http::fake()`,
  et un résolveur DNS injecté (`HostResolver`) doublé en test. `Http::preventStrayRequests()` dans
  les tests de lecture d'URL.
- **Aucun identifiant de modèle hors de `config/ai.php`** (`scripts/check-ai-usages.mjs`).
- **Le contenu collecté est une donnée** : il arrive au modèle par `ExternalContent::wrap()`,
  l'agent n'implémente ni `HasTools` ni `HasSkills` et implémente `HasStructuredOutput`
  (`ExternalContentPolicy`, ADR-0076 §10).
- **La classe de données de l'usage est `personnelle`** : la passerelle ne masque pas les numéros
  (`AiDataGuard::prepare()` ne masque que `publique`) — c'est voulu, l'extraction doit les lire.
- **Codes, jamais de prose** dans les réponses et les motifs d'état : `radar.*`, `ai.*`
  (`abort_code_unless`, `ProseLitteraleInterditeTest`).
- API : `Base\Controller` + `$this->json()` / `$this->paginated()` ; `FormRequest` sur
  `BaseFormRequest` ; enums sous `app/Models/Enums/` ; modèles sur `AbstractModel` avec
  `$queryFields`, `$requestFilterable`, `$requestSortable` ; ressources sur `BaseResource`
  (`iso()` pour les `datetime`).
- Migrations PostgreSQL : `jsonb` jamais `json`, `string()` jamais `enum()`, index et FK nommés
  explicitement sous 63 caractères, FK indexées, `down()` exact. Pas de `try/catch` sur une
  violation d'unicité dans une transaction : `insertOrIgnore` puis relecture.
- **Aucune photo n'est téléchargée** : seules les URL source sont gardées (`photo_urls`).
- Front : textes next-intl (`fr`, `en` ; `wo` = le texte français tel quel, wolof en pause) ;
  jetons du design system (`check-super-admin-tokens.mjs`) ; `EmptyState`/`ErrorState` de
  `@/components/feedback` ; préfixe `/api` écrit par l'appelant avec `apiRequest`/`useApiQuery` ;
  sparse fieldsets (`fields[radar_listings]=…`).
- `./vendor/bin/pint` avant chaque commit ; commits en français, préfixe conventionnel,
  `(TCK-2386)`, ligne `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Un agent délégué ne lance que ses tests** (`php artisan test <fichier>`, `npx vitest run
  <fichier>`) et les gardes concernées (`node scripts/check-*.mjs`). Jamais la suite entière.
- **Chaque test de correctif se vérifie par ablation** : retirer le mécanisme, constater le rouge,
  le remettre. L'ablation se fait par copie de sauvegarde du fichier, jamais `git stash`.

### Task 2 : lire une URL sans s'exposer (`UrlFetcher`, `HtmlCleaner`)

**Produit :**

- `interface HostResolver { /** @return list<string> */ public function resolve(string $host): array; }`
  et `DnsHostResolver` (A + AAAA, `dns_get_record`), lié dans le conteneur.
- `UrlFetcher::fetch(string $url): FetchedPage` (`FetchedPage{ string $url (finale), int $status,
  string $body, ?string $contentType }`). Lève :
  - `RadarFetchRefused` (propriété `code`) : `radar.fetch.invalid_url` (schéma autre que
    http/https, hôte vide, port hors 80/443), `radar.fetch.airbnb`, `radar.fetch.private_address`,
    `radar.fetch.robots`, `radar.fetch.too_many_redirects`, `radar.fetch.too_large`,
    `radar.fetch.not_html`, `radar.fetch.http_error`, `radar.fetch.timeout`,
    `radar.fetch.unresolvable` ;
  - `RadarFetchDeferred` (propriété `retryAfterSeconds`) quand le domaine a été lu il y a moins
    de `radar.fetch.min_delay_seconds`.
- Règles (ADR-0077 §10, contraintes du ticket) :
  - **chaque saut** (URL de départ et chaque `Location`) : schéma, hôte, résolution DNS, **toutes**
    les adresses résolues contrôlées, refus si une seule est privée/réservée : `127.0.0.0/8`,
    `10/8`, `172.16/12`, `192.168/16`, `169.254/16` (métadonnées), `100.64/10`, `0/8`,
    `224/4` et au-delà, `::1`, `::`, `fc00::/7`, `fe80::/10`, IPv4 mappée en IPv6, et un hôte
    littéral IP soumis aux mêmes règles. `localhost` et `*.localhost` refusés sans résolution ;
  - la connexion est **épinglée** sur l'adresse contrôlée (`CURLOPT_RESOLVE` `host:port:ip`) : pas
    de seconde résolution entre le contrôle et la connexion (rebinding DNS) ;
  - redirections suivies **à la main** (`allow_redirects => false`), au plus
    `radar.fetch.max_redirects` (3) ;
  - `robots.txt` du domaine lu par le même chemin protégé, mis en cache un jour
    (`RobotsTxt::allows(string $robots, string $path, string $userAgent): bool` — groupes
    `User-agent` propre puis `*`, `Allow`/`Disallow` par plus long préfixe, `*` et `$` gérés ;
    absent (4xx) → tout permis ; 5xx ou injoignable → tout refusé) ;
  - une requête à la fois par domaine et un délai minimal : `Cache::add('radar:fetch:'.$host, …,
    min_delay)` ; échec → `RadarFetchDeferred` ;
  - délai d'expiration court (`timeout` 10 s, `connect_timeout` 5 s), corps borné
    (`radar.fetch.max_bytes`, 2 Mo : en-tête `Content-Length` et taille lue), `User-Agent`
    `config('radar.fetch.user_agent')` ;
  - Airbnb : `airbnb.<tld>` et sous-domaines, `abnb.me` — refusé avant toute résolution.
- `HtmlCleaner::clean(string $html, string $baseUrl): CleanedPage` (`CleanedPage{ string $text,
  ?string $title, list<string> $photoUrls }`) : DOM ; retire `script`, `style`, `noscript`, `svg`,
  `iframe`, `nav`, `footer`, `form`, `header` ; titre de `og:title` ou `<title>` ; texte de
  `og:description` + corps, blancs repliés, borné à `radar.fetch.max_text_chars` (20 000) ;
  photos : `og:image` + images JSON-LD, absolutisées, `http(s)` seulement, dédoublonnées, au plus 20.

**Tests :** `tests/Feature/Radar/RadarUrlFetcherTest.php` — IP privée littérale, `localhost`,
`169.254.169.254`, **redirection vers une IP privée (AC1 : la cible n'est jamais contactée —
`Http::assertSentCount` / `assertNotSent` sur l'hôte de la cible)**, DNS qui résout en privé,
DNS qui résout en mixte (public + privé → refus), `robots.txt` qui interdit, `robots.txt` absent,
Airbnb, trop de redirections, corps trop gros, délai par domaine → `RadarFetchDeferred` ;
`tests/Unit/Radar/RobotsTxtTest.php` ; `tests/Unit/Radar/HtmlCleanerTest.php`. Le test de
l'épinglage vérifie l'option `curl` passée à la requête (`Http::assertSent` sur les options si le
faux client les expose ; sinon un test unitaire de la fonction qui construit les options).

### Task 4 : la normalisation par du code

**Produit :**

- `RadarAmountParser::parse(string $text): ?array{amount: int, period: ?string}` — « 1M5 » →
  1 500 000 ; « 1,5M », « 1.5 million(s) » → 1 500 000 ; « 45 millions » → 45 000 000 ;
  « 350K », « 350 mille » → 350 000 ; « 450.000f/mois », « 450 000 FCFA par mois » → 450 000,
  `month` ; « 25.000.000 » → 25 000 000 ; « 35 000/jour », « la nuitée » → `day` ; « /an » →
  `year`. `period` prend les valeurs de `RentPeriod` (relire l'enum ; si `year` n'existe pas, ne
  pas l'inventer : `null`). Chiffres arabes et pleine chasse via `PhoneMasker::normalizeDigits()`.
  Rien de lisible → `null`.
- `RadarNeighborhoodMatcher::match(string $text, ?string $cityText): array{neighborhood_id: ?int,
  suggestions: list<array{id: int, name: string, city: string}>}` — par du code, jamais par l'IA
  (ADR-0062) : clé `GeoNeighborhoodResolver::cle()` ; quartiers actifs seulement (fusionné → sa
  cible, refusé exclu) ; ville connue → bornée à la ville. Exactement un quartier de même clé →
  rattaché ; plusieurs (même nom dans plusieurs villes) → suggestions ; aucun → suggestions par
  préfixe ou inclusion de la clé (« Liberté » → Liberté 1…6), au plus 5, **jamais un choix**.
- `ExtractionNormalizer::normalize(array $raw, ?string $sourceText): array` — rend, par champ,
  `{value, confidence, evidence, flags: list<string>}` (+ `raw` pour `price`, + `neighborhood_id`
  et `suggestions` pour `neighborhood`) :
  - **confiance forcée à `low` quand `evidence` est vide ou nul** (AC3), et quand le passage
    n'apparaît pas dans le texte source (comparaison après repli des blancs et de la casse ;
    drapeau `evidence_not_in_source`) — pas de contrôle de présence sans texte source (captures) ;
  - `price` → `RadarAmountParser` ; `rent_period` déduite du prix si absente ;
  - **bornes de vraisemblance** dans `config/radar.php` (`bounds`) : loyer mensuel 15 000 …
    20 000 000 ; loyer journalier 5 000 … 1 000 000 ; vente 1 000 000 … 10 000 000 000 ; surface
    5 … 100 000 m² ; chambres 0 … 30 ; salles d'eau 0 … 20. Hors bornes → drapeau
    `out_of_bounds` et confiance `low` ; la valeur reste (l'humain tranche) ;
  - valeurs d'enum inconnues (`property_type`, `contract`…) → `null`, drapeau `invalid_value` ;
  - `phones` → `RadarPhone::canonical()` ; les invalides tombent.

**Tests :** `tests/Unit/Radar/RadarAmountParserTest.php`,
`tests/Feature/Radar/ExtractionNormalizerTest.php` (AC3, AC4 — « 1M5 », « 450.000f/mois », loyer

### Task 5 : la saisie, les droits et les routes

**Produit :**

- `PlatformAbility::RadarOperate` (posé en tâche 3) dans la liste `support` de `forLevel()`.
- `StoreRadarListingRequest` (`authorize()` : `true` — la route est gardée par `super-admin` +
  `platform-can:platform.radar.operate`, comme les FormRequests de la console IA) : **exactement
  un** de `urls` (tableau 1 … 20 d'URL http/https, ≤ 2 048 caractères), `text` (chaîne 20 … 20 000)
  ou `captures` (1 … 10 fichiers `image/jpeg|png|webp`, ≤ 8 Mo chacun — bornes dans
  `config/radar.php`) ; `source_site` optionnel (valeurs de `RadarSourceSite`) pour le texte et
  les captures. Une URL Airbnb → 422, code `radar.url.airbnb`.
- `RadarListingIntake` :
  - `fromUrls(list<string>, User): list<array{listing: RadarListing, existing: bool}>`,
    `fromText(string, ?RadarSourceSite, User)`, `fromCaptures(list<UploadedFile>, ?RadarSourceSite, User)` ;
  - empreinte (`content_fingerprint`) : texte → `sha256('text|'.<texte replié : chiffres
    normalisés, blancs repliés, minuscules>)` ; URL → `sha256('url|'.<URL canonique : hôte en
    minuscules, sans fragment, sans paramètres `utm_*`/`fbclid`, sans `/` final>)` ; captures →
    `sha256('captures|'.<empreintes SHA-256 des fichiers d'origine, triées, jointes>)` ;
  - **empreinte déjà connue → la fiche existante, sans job** (AC2) ; course d'insertion :
    `insertOrIgnore` puis relecture ;
  - **texte : téléphones lus par `RadarPhone::fromText()`** ; si l'un a son empreinte HMAC chez un
    annonceur `do_not_contact_at` non nul → étape `do_not_contact`, annonceur rattaché, **aucun
    job, aucun appel IA** (AC6) ;
  - captures : réencodées par `intervention/image` (EXIF retiré — un test lit l'EXIF du fichier
    stocké et n'y trouve rien), stockées dans `radar_captures`, empreinte SHA-256 de l'original en
    propriété du média (`sha256`) ;
  - `source_site` d'une URL : `RadarSourceSite::fromHost()` ;
  - sinon : étape `captured` et `ExtractRadarListing::dispatch($listing->id)` (après commit).
- `RadarListingController` : `store` (201, `{data: [{id, stage, existing}]}`), `index`

### Task 6 : le job d'extraction

**Produit :** `App\Jobs\Radar\ExtractRadarListing implements ShouldQueue` (`$listingId`) :

- idempotent : ne fait rien si l'annonce n'est plus `captured` ;
- `retryUntil()` = 48 h ; `extraction_attempts` incrémenté à chaque passage ;
- **URL sans texte** : `UrlFetcher` + `HtmlCleaner` → `raw_text`, `photo_urls` ;
  `RadarFetchDeferred` → `release(retryAfter)` ; `RadarFetchRefused` → `extraction_failed`,
  `stage_reason` = son code (le front propose alors texte ou captures) ;
- **refus STOP** : téléphones du texte (`RadarPhone::fromText`) contre les empreintes refusées →
  `do_not_contact`, sans appel IA ;
- appel : `AiGateway::run(new AiRequest('radar.extraction', ExternalContent::wrap($site, $texte),
  [AiDataClass::Personnelle], actor: capturedBy, subject: $listing, attachments: <captures en
  Image::fromStorage(…) ou fromPath via PrivateMediaAccess>))` — jamais `getPath()` ;
- `AiRefused` budget ou coupe-circuit → `stage_reason` `ai.budget` / `ai.kill_switch`, l'annonce
  reste `captured` (« en attente »), `release(1800)` ; `AiRefused` autre (droits, données) →
  `extraction_failed` + code ;
- `AiUnavailable` (tous les fournisseurs en panne, réponse coupée) → `stage_reason`
  `ai.providers_unavailable`, `release()` espacé selon `extraction_attempts` (60, 300, 900, 3 600 s) ;
- sortie structurée nulle ou invalide → une nouvelle tentative, puis `extraction_failed`
  `radar.extraction.invalid_output` (source conservée) ;
- succès : `ExtractionNormalizer` → `extracted`, `extracted_at`, étape `extracted`,
  `stage_reason` nul ; annonceur par `RadarAdvertiserDirectory::findOrCreate(string $e164)`
  (premier téléphone valide ; nom affiché, nature et indices posés s'ils sont vides) ; s'il est
  `do_not_contact` → étape `do_not_contact` ;
- `failed()` (délai dépassé) → `extraction_failed` avec le dernier motif.

**Tests :** `tests/Feature/Radar/ExtractRadarListingTest.php` (faux agent : champs enregistrés,
confiance forcée sans passage, budget épuisé ⇒ en attente sans échec, panne ⇒ en attente puis
réessai, sortie invalide ⇒ `extraction_failed`, URL refusée ⇒ `extraction_failed` + code, STOP
